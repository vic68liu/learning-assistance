# ADR-0005: 未成年人数据采集、脱敏与留存

- Status: **Proposed**（待人工批准，涉及合规须由项目负责人最终确认）
- Date: 2026-11-01
- Deciders: OpenCode 起草，待项目负责人 + 家长同意机制确认
- Related: R23、R24、ADR-0003

## 背景

PoC 的输入是**孩子的手写作业照片**。这类素材同时包含：

- 直接身份信息：姓名、班级、学号（常写在作业抬头）、可能的脸部（自拍式上传）
- 间接身份特征：**个人笔迹**、书写习惯、错题分布本身也构成个体学习画像
- 敏感结论：错误诊断记录如果泄露，等同于公开孩子的学习弱势

原方案只提了"使用 pseudonymous ID"和"不允许 API Key 入项目文件"，
没有回答采集、留存、出域这三件事。而项目里最容易犯的错误，
恰好是"为了测试方便，把真实作业照片放进仓库"。

## 决策

### 1. 仓库红线（不可绕过）

| 内容 | 规则 | 保障 |
|---|---|---|
| 作业照片/扫描/录音 | **任何情况下不入库**，包括 `test-data/` | `.gitignore` 全量排除图片/PDF/音频扩展名 |
| 真实姓名/校名/班级/学号 | 不出现在任何文件内容或文件名中 | 校验脚本扫描常见凭证与身份字段（P4 前加入） |
| 从照片复制出的原文 | 禁止直接作为测试数据入库 | 必须人工重打或合成（见 §3） |
| API Key | 只走环境变量 | `scripts/validate_skills.py` 做密钥形态扫描 |

明确禁止 `git add -f` 绕过忽略规则。**这是本项目唯一"宁可无法测试也不妥协"的条款。**

### 2. 数据分层

```
L0 原始素材    作业照片、录音            → 只存在于 student-data/<id>/homework/<hw_id>/raw/
                                          本地，永不入库，任务完成后可删
L1 结构化数据  analysis/diagnosis/evidence → student-data/，pseudonymous ID，不入库
L2 测试素材    合成题干与作答文本         → test-data/，可入库
L3 评测记录    model_output / scores      → benchmark/，原始响应体不入库（可复现则记录 run manifest）
```

### 3. 从真实作业到 test-data 的唯一合法路径

```
真实作业（L0/L1）
  → 教师/家长人工识别出"错误模式"这一抽象信息（如：去括号只对首项变号）
  → 用合成数字**重新造一道同结构题**（改变所有数字、系数、项数）
  → 人工写出 gold 答案，用 scripts/math_check.py 验算
  → 记录到 test-data/，并标注 provenance: "synthetic_from_observed_error_pattern"
```

要点：保留的是**认知错误模式**，丢弃的是**这个孩子的具体数据**。
错题分布本身是个人特征，因此合成时不得保留原数字与原题干措辞。

### 4. 留存期限（PoC 默认值，需家长告知）

| 数据 | 默认留存 | 依据 |
|---|---|---|
| L0 原始照片 | 30 天 | 仅需覆盖"分析出错可重跑"窗口 |
| L1 结构化与 evidence | 会话期间保留，PoC 结束导出后删除 | append-only 要求的是不篡改，不是永久保留 |
| L2 合成素材 | 无限期（无个人信息） | 可入 Git |

### 5. 出域与第三方

- 调用云端模型时，作业内容会离开本机 —— PoC 必须**在家长知情同意下**进行，
  且只发送题目的**转录文本**而非原始照片（若 OCR 在服务端做，则无法回避，需在同意书中写明）
- 禁止把学生数据发送给未批准的第三方服务、分析工具、崩溃上报
- 日志（含 OpenClaw 侧）不得记录原文中的身份字段；PoC 阶段约定：**日志只记 ID，不记内容**

### 6. 面向学生的输出伦理（与 R20 呼应）

- 学习报告给家长看，措辞不得包含能力判断（"天赋不足""粗心"）
- 诊断结论必须带证据编号，家长可追问"凭什么这么说"
- `unknown` 状态必须在报告中如实呈现为"还没测到"，不得渲染成"没掌握"

## 备选方案

1. **照片入库但打码姓名** —— 否决。打码不可靠（OCR 常失败、笔迹本身是特征），
   且 Git 历史里删不干净；一旦入库就有永久泄露风险，收益只是"测试方便"。
2. **全部内存处理不落地** —— 否决。与 ADR-0003 的 append-only 证据要求冲突，
   没有可追溯证据就无法支撑诊断结论。
3. **用公开教辅题替代真实作业做测试** —— 部分采纳为 L2 主要来源，
   但它无法覆盖真实手写与真实错误分布，因此不能作为唯一来源。

## 后果

- 正面：仓库永远可以安全地推到远端/交给他人审阅；测试数据的来源可解释。
- 负面：合成数据会**低估真实手写场景的难度**，因此 PoC 结论必须标注这一局限；
  家长同意流程是 PoC 的硬前置，未走完不得开始采集真实作业。
- 债务：图片排除依赖扩展名，改名 `.jpg.txt` 之类可绕过 —— 需在 CI 加内容嗅探（P10 前）；
  "日志只记 ID"目前靠约定，无自动化保障。

## 验证

- Layer 1：`tests/` 增加密钥/身份字段扫描用例（构造含 `sk-` 与含"姓名"字段的样例，断言被拒绝）
- Layer 2：`scripts/validate_skills.py` 的凭证扫描必须覆盖本项目文件自身
- 流程验证：提交前人工执行 `git ls-files | grep -Ei "student-data|\.env|key"` 应为空
  （README 已把该命令列入必跑四条）

**当前状态**：家长知情同意流程**尚未建立**，因此本项目当前不得使用任何真实学生数据；
所有测试数据必须是合成的。
