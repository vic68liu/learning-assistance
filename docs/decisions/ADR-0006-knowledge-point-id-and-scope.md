# ADR-0006: 知识点 ID、废弃策略与 PoC 范围

- Status: **Proposed**（教材版次待人工核对，见 REVIEW-QUEUE 第 1 项）
- Date: 2026-11-01
- Deciders: OpenCode 起草；T1 批次范围已获项目负责人确认（人教版 / 仅七上）
- Related: R13、R14、R22、ADR-0002、ADR-0003

## 背景

四个 Skill 都依赖知识点 ID，而 R14 规定 ID 的唯一来源是 `knowledge-base/grade-7-math.json`。
要让这条规则可执行，必须先回答三个问题：

1. ID 长什么样，才能既反映教材结构、又不因教材微调而崩溃？
2. 知识点被删除时，引用它的历史 evidence 怎么办？（R22 的直接冲突点）
3. PoC 覆盖多少知识点，人工审核成本才现实？

## 决策

### 1. ID 文法

```
g7.math.<册码><章序>.<节序>.<点序>
        a04        .02      .04        →  g7.math.a04.02.04

册码  a = 七年级上册   b = 七年级下册
章序  该册内章号，两位，01..06（七上）
节序  该章内节号，两位，取自教材 x.2 的第二段
点序  该节内诊断点序号，两位，单调递增
```

约束：

- 册码进 ID 的原因是**必要而非美观**：北师大版等版本七上/七下各自从"第一章"重新编号，
  只用章号会产生歧义。人教版章号连续（1–10），但保留册码可让本知识库结构跨版本复用。
- 三级小节（如 `4.1.1 单项式`）**不进 ID**，存 `subsection_title` 字段。
  否则 ID 会长到无法手抄，且教材在三小节层重排会迫使改 ID。
- **点序永不复用、永不回填**：即使某点废弃，其序号也不给新点使用。
- ID 一经 `reviewed` 即永久占用（见 §2）。

### 2. 废弃而非删除

```json
{ "id": "g7.math.a02.03.04", "title": "近似数与有效数字",
  "deprecated": true, "deprecated_at": "2026-11-20",
  "replacement_id": "g7.math.a02.03.05", "deprecated_reason": "与科学记数法合并为一个诊断点" }
```

- 禁止物理删除条目。理由：历史 `evidence.jsonl` 里的 `knowledge_point_id`
  必须永远能解析到某个条目，否则 R22（不覆盖历史证据）与 R15/R16（不得凭一次答题定论）
  会失去数据基础。
- `deprecated` 条目**不得被新的 Skill 输出引用**（Layer 2 校验项），
  但仍可被 `knowledge-diagnosis` 读取用于历史画像。
- 合并/拆分知识点时，`replacement_id` 必填；拆分可指向多个 ID，用数组。

### 3. 粒度规则

见 `knowledge-base/README.md`。判定"独立成诊断点"的三条标准
（可分离失败 / 补救动作不同 / 错误类型分布不同）。

粒度不足会直接导致 `learning-plan` 与 `math-tutor` 无法工作：
一个点必须能独立出一道验证题。这是硬约束，不是审美偏好。

### 4. PoC 范围

| 范围 | 决定 | 理由 |
|---|---|---|
| 教材 | 人教版 | 项目负责人确认 |
| 册次 | **仅七年级上册** | 控制人工审核成本 |
| 章 | **第 1–5 章（数与代数）** | 见下 |
| 第 6 章 几何图形初步 | **暂缓，不入库** | 见下 |
| 批次 | T1（26 个诊断点）先建，T2（其余 26 点）后置 | 26 点 × 3 题 = 78 道人工审题，与 P9 的 ≥30 案例门槛匹配 |

**第 6 章暂缓的三条理由**（这是范围决策中最重要的一条，必须写清）：

1. **验算失效**：ADR-0002 的 sympy 管线只对代数式与方程有效。三视图、线段图、
   角的和差需要图形语义，符号验算做不了 → `verification_status` 全量落在 `needs_human_check`，
   `program_verified` 这个档位在本 PoC 中就失去了意义。
2. **OCR 是未验证环节**：几何题必须读图，而图像输入路径是整个方案里唯一没做过 spike 的
   外部依赖（AGENTS.md 第 10 节缺口 2）。把它和 Skill 逻辑混在第一轮测试里，等于给未来的
   归因工作埋雷。
3. **归因污染**：ADR-0004 要求报告能区分五类失败原因。几何题混入后，
   分数下降将无法判断是模型能力、图像输入、还是 Skill Prompt 的问题。

因此：**几何题进入知识库的前提是 OCR spike 通过**，与 Skill 开发解耦。

### 5. `textbook_version` 字段必须落在每条知识点上

PoC 会同时存在"2012 旧版"与"2024 新版"教材的使用者（新版从 2024 秋起在七年级铺开，
但章结构不同：旧版 4 章、新版 6 章）。每条知识点记录版本，未来支持另一版本时
不需要重排 ID，只需新增章序。

### 6. `origin` 与审核状态

| 字段 | 取值 | 含义 |
|---|---|---|
| `origin` | `human_outline` / `inferred` | 条目来自人工大纲，还是 OpenCode 从结构推断 |
| `review_status` | `reviewed` / `pending_review` / `rejected` | 人工审核状态 |

**关系边同样有 `origin`**。规则：`origin: inferred` 且 `review_status: pending_review` 的关系边
**禁止用于给出掌握度结论**（可用于生成待确认问题）。这是把 R13/R14 从口号变成可校验点的机制。

## 备选方案

1. **UUID / 自增整数作知识点 ID** —— 否决：日志、Prompt、人工沟通都要引用 ID，
   不透明的 ID 会迫使人到处查表，而教材结构信息正是诊断推理需要的上下文。
2. **用教材页码或习题编号作 ID** —— 否决：页码逐年微调，且同一知识点可能跨页。
3. **允许物理删除 + 历史 evidence 指向 `unknown`** —— 否决：直接破坏 R22，
   并让"多次错误证据"的计数在删除后不可复现。
4. **PoC 覆盖七上全部 52 点** —— 否决：需约 156 道人工审题，在第一个 Skill 验收前投入
   这些成本会把 P4 的反馈周期拖长数倍。
5. **几何章纳入但只处理纯计算题（角度计算）** —— 部分采纳为未来方案：
   角度数值计算确实可验算，但仍需读图获得已知条件，故仍受缺口 2 阻塞。

## 后果

- 正面：ID 自解释、可手抄、可按章聚合；废弃不破坏历史；范围收敛让 P4 能在短周期内验收。
- 负面：**当前版次未经实体书核对**，如果实际教材与建模不符，需要重排章序
  （缓解：章序集中在 `chapter.code` 字段，重排成本可控，且此时还没有历史 evidence）。
  几何被排除在 PoC 之外，期末综合卷会出现几何题 —— PoC 的能力边界必须在报告里如实写明。
- 债务：多教材版本支持（`textbook_version` 已预留但无第二条数据）；
  七下与 T2 批次待建；知识点与"课标要求层次"（了解/理解/掌握/运用）的映射尚未建模。

## 验证

- Layer 1：`tests/test_validate_knowledge_base.py` 断言：
  ① ID 匹配文法且唯一 ② `PREREQUISITE` 构成 DAG（`graphlib.TopologicalSorter`）
  ③ 关系边 `from`/`to` 均存在 ④ `deprecated` 条目不可被非历史字段引用
  ⑤ 关系枚举取值合法
- Layer 2：Skill 输出中所有 `knowledge_point_id` 必须存在于知识库**且未 deprecated**，
  否则判 `unmapped` 违规（R13）
- 实测结果见 commit 3/4 的脚本输出

**当前状态**：T1 的 26 个诊断点已按 2024 新版目录建模，
顶层 `review_status: pending_review`，阻塞项为 REVIEW-QUEUE 第 1 项（实体书核对）。
